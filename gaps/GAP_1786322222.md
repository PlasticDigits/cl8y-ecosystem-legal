**Generated:** 2026-08-10

**Scope:** Full repository (`api/`, `bot/`, `web/`, `packages/cl8y-clickwrap/`, CI, ops scripts, legal source)

## Executive summary

CL8Y Legal is a coherent **off-chain** Terms & Conditions acceptance platform: global versioned terms, per-property signatures (hostname or Telegram chat id), Axum API, Vite signing portal, clickwrap JS/React SDK, and a Teloxide enforcement bot.

The **EVM path is production-plausible** (unit + integration + Playwright). Several other identity paths are broken or unproven against real wallets:

| Path | Verdict |
|------|---------|
| EVM (`personal_sign` / viem) | Solid |
| Telegram Login Widget | Solid |
| Telegram WebApp `init_data` | **Broken HMAC** (critical) |
| Solana (Phantom `signMessage`) | **Verify envelope mismatch** (critical) |
| Terra Classic (ustr-cmm wallets) | **Resolved (portal)** — ADR-036 verify (issue `#1`); Open-in-Keplr (issue `#9`); Station/Leap/Cosmostation injected + LUNC Dash/Galaxy WC (issue `#11`; see `skills/terra-classic-adr036/SKILL.md`) |

Secondary themes: thin non-EVM tests, portal UX (Solana/Telegram still omit on-page terms; EVM/Terra Classic addressed in GitLab #2 / `web/src/signShell.ts`), and no on-chain/gas surface to optimize.

## 3. Security

### Critical

1. **Telegram WebApp HMAC incorrect** — Spec: `secret = HMAC_SHA256(key="WebAppData", msg=bot_token)`. Code: `HMAC_SHA256(key="WebAppData", msg=SHA256(bot_token))`. Mini App / bot WebApp signing path cannot verify correctly. Only Login Widget is unit-tested (`api/src/telegram.rs`).

2. **Solana verification ≠ wallet signing** — API wraps message in `0xff || "solana offchain" || len_le || msg` before ed25519 verify; portal passes UTF-8 bytes to `provider.signMessage`. Production Phantom-style flows will fail (or would only pass if a wallet coincidentally used the same envelope—current portal does not).

3. ~~**Terra / Keplr path non-functional**~~ **Resolved (portal scope, issues `#1` / `#9` / `#11`)** — ADR-036 verify + ustr-cmm wallet matrix + Open in Keplr. Invariants: `skills/terra-classic-adr036/SKILL.md`.

### High

4. **Unauthenticated `POST/GET /update_terms`** — ~~Triggers outbound GitLab fetch; only 1 req/s/IP.~~ **Addressed (issue #3):** `POST /update_terms` requires `ADMIN_TOKEN` Bearer; GET removed; see `api/src/routes/update_terms.rs` + [`skills/security-ops/SKILL.md`](../skills/security-ops/SKILL.md).

5. **Default `ADMIN_TOKEN=dev-admin-token`** if unset — ~~silent default~~ **Addressed (issue #3):** fail-fast unless `ALLOW_INSECURE_DEFAULTS=true`; see `api/src/config.rs`.

6. **`X-Forwarded-For` trusted blindly** for rate limits — ~~spoofable~~ **Addressed (issue #3):** peer IP by default; `TRUSTED_PROXY_CIDRS` + rightmost-hop policy in `api/src/rate_limit.rs`.

7. **Open redirect** via `redirect_uri` — ~~no allowlist~~ **Addressed (issue #3):** portal allowlist (`VITE_REDIRECT_URI_ALLOWLIST`) + SDK `sanitizeRedirectUri`; unsafe URIs do not navigate.

8. **Bot treats API errors as unsigned** (`unwrap_or(false)`) — ~~fail-open into reminders/kicks~~ **Addressed (issue #5):** fail-closed via `bot/src/compliance.rs` (`Unknown` → no mark/kick); see [`skills/bot-enforcement/SKILL.md`](../skills/bot-enforcement/SKILL.md).

9. **Bot status-check on every group message** — self-inflicted API load / rate-limit collisions.

### Medium

10. Open property auto-upsert (`api/src/property.rs`) — table fill / junk properties.  
11. `ALLOW_LOCALHOST_PROPERTY` defaults **true**.  
12. Admin / Telegram hash compares not constant-time; `subtle` crate declared but unused.  
13. ~~Terra address validation is prefix-only~~ **Resolved** — bech32 HRP `terra` + checksum + 20-byte payload (`api/src/account.rs`).  
14. Signature `ON CONFLICT DO UPDATE` overwrites proof (replay/refresh semantics unclear for auditors).  
15. No CSP on portal; Telegram scripts loaded on **every** page (`web/index.html`).  
16. CORS methods/headers `Any` even when origins are restricted.  
17. Unbounded per-IP limiter map (DashMap growth).  
18. Kick path does not exempt group admins/creators.

### Lower / ops

19. No graceful shutdown / request timeouts on API.  
20. Hardcoded `t.me/cl8ytermsbot` in bot config.  
21. No root `LICENSE` file (SDK package.json claims MIT).  
22. Compose ships only Postgres; README prefers host Postgres — easy local/prod drift.

## 7. Gas optimizations

**N/A.** There are no smart contracts, RPC submits, or on-chain settlement. EVM/Solana/Terra are **identity proofs only** (off-chain signatures stored in Postgres).

If on-chain attestation is ever added, expect gaps around: content hash binding, EIP-712/SIWE/CAIP-122, replay protection, and batch attestation gas — none of that exists today.

**Related crypto efficiency (off-chain):** prefer well-tested codecs (`bs58` npm) over custom base58; fix Terra ADR-036 hashing once rather than “optimizing” raw verify.

## 8. DRY, readability, language best practices

### DRY

| Issue | Notes |
|-------|-------|
| `api/src/terms_sync.rs` | ~116-line orphan duplicate of `terms/sync.rs`; **not** `mod`’d in `lib.rs` — delete or wire one |
| Sign page chrome | `evm.ts` / `solana.ts` / `terra.ts` nearly identical shells — extract shared renderer |
| Message format | **Good:** web re-exports SDK; golden test vs Rust — keep dual TS/Rust implementations in sync |
| Telegram submit | Route builds message then `submit_telegram` rebuilds/rechecks |

### Readability

- API module boundaries are clear and idiomatic for Axum 0.8.
- Telegram web page is the densest (~150 lines, three modes).
- Bot message/enforcement split is understandable.

### Best-practice gaps

**Rust / Axum / SQLx**

- Prefer `sqlx::query!` / offline mode for compile-time SQL checks  
- Constant-time compares for tokens/hashes (`subtle`)  
- ~~Request body limits~~ (64 KiB `DefaultBodyLimit` on API router); still missing timeouts, graceful shutdown, `/health` + `/ready`  
- Fail-closed bot compliance when API errors  
- Cache signature status in bot (TTL) instead of per-message calls  
- Remove dead `terms_sync.rs` and unused `subtle` (or use it)

**TypeScript / React**

- Type `submitWallet` / `submitTelegram` bodies (today `Record<string, unknown>`)  
- `useSignatureStatus` default `client = createClient()` recreates client every render — unstable deps; memoize like `TermsGate`  
- Prefer `bs58` package; fix tests  
- Align Network enums carefully (`"Solana"` SDK vs `"SOLANA"` API) — mapping exists but is easy to misuse  
- Abort in-flight status fetches; consider `useEffectEvent` for `onError`

**Frontend security hygiene**

- CSP allowing Telegram origins explicitly  
- Validate/allowlist `redirect_uri`  
- Load `telegram-web-app.js` only on Telegram routes
